# 工事写真分類の階層構造（国土交通省写真管理基準準拠）

## 重要な前提知識

工事写真の分類は国土交通省の写真管理基準に基づく**5階層構造**で管理される。
この階層構造を理解せずにマスタデータを編集すると、意味不明なエントリーが作成される原因となる。

## 階層構造（上から下へ）

```
写真区分（photoCategory）
  └─ 工種（workType）
       └─ 種別（variety）
            └─ 細別（detail）
                 └─ 備考（remarks）
```

### 各階層の説明

| 階層 | 英語名 | 説明 | 例 |
|------|--------|------|-----|
| 写真区分 | photoCategory | 写真の大分類 | 品質管理写真、施工状況写真、材料検収写真 |
| 工種 | workType | 工事の種類 | 舗装工、土工、構造物工 |
| 種別 | variety | 工種の下位分類 | 舗装打換え工、盛土工、擁壁工 |
| 細別 | detail | 具体的な作業種別 | 表層工、上層路盤工、下層路盤工 |
| 備考 | remarks | 実際の撮影内容・測定項目 | アスファルト混合物温度測定、現場密度測定 |

## 絶対に守るべきルール

### 1. 階層を勝手に増やさない

❌ 間違い：
```
表層工
  └─ 温度測定工        ← これは存在しない！
       └─ 温度管理
```

✅ 正解：
```
表層工
  └─ アスファルト混合物温度測定
```

### 2. 「〜工」は細別（detail）レベルまで

- 工種：舗装**工**
- 種別：舗装打換え**工**
- 細別：表層**工**、上層路盤**工**
- 備考：「工」は付けない（アスファルト混合物温度測定、現場密度測定）

❌ 間違い：現場密度測定**工**
✅ 正解：現場密度測定

### 3. 備考レベルは具体的な測定・確認項目

備考（remarks）に入るのは：
- 温度測定（アスファルト混合物温度測定）
- 密度測定（現場密度測定）
- 厚さ確認
- 出来形確認
- 材料確認

### 4. 写真区分ごとの典型的な構造

#### 品質管理写真
```
品質管理写真
  └─ 舗装工
       └─ 舗装打換え工
            ├─ 表層工
            │    └─ アスファルト混合物温度測定
            └─ 上層路盤工
                 └─ 現場密度測定
```

#### 施工状況写真
```
施工状況写真
  └─ 舗装工
       └─ 舗装打換え工
            ├─ 表層工
            │    └─ 敷均し状況、転圧状況
            └─ 上層路盤工
                 └─ 敷均し状況、転圧状況
```

## よくある間違いパターン

| 間違い | 正解 | 理由 |
|--------|------|------|
| 温度測定工 | アスファルト混合物温度測定 | 「工」は細別まで。備考に「工」は付けない |
| 現場密度測定工 | 現場密度測定 | 同上 |
| 品質管理（工種として） | 品質管理写真（写真区分として） | 階層レベルが異なる |

## マスタ編集時の確認事項

1. 新しいエントリーを追加する前に、既存の階層構造を確認する
2. 追加するエントリーがどの階層レベルに属するか明確にする
3. 「〜工」を付けるのは細別（detail）レベルまで
4. 備考（remarks）レベルには具体的な測定・確認項目を入れる
5. 既存の類似エントリーと命名規則を揃える

## 【重要】マスタ保護ルール

### AIによるマスタ書き換え禁止

**ユーザー承認なしにマスタデータを変更してはならない。**

これは最重要ルールである。AIが「創作」した謎エントリー（例：温度測定工）がマスタに混入すると、以後そのエントリーが正解として扱われ、データ品質が劣化する。

### 許可される操作

| 操作 | AI単独 | ユーザー承認後 |
|------|--------|----------------|
| マスタの読み取り | ✅ | - |
| 既存エントリーへのマッチング | ✅ | - |
| 新規エントリーの提案 | ✅ | - |
| マスタへの新規追加 | ❌ | ✅ |
| 既存エントリーの修正 | ❌ | ✅ |
| エントリーの削除 | ❌ | ✅ |

### 未知の分類が出現した場合のフロー

```
1. AI解析で写真を分類
2. マスタに該当エントリーがある → そのまま使用
3. マスタに該当エントリーがない：
   3-1. 既存エントリーとの類似度を計算
   3-2. 類似度が閾値以上（エイリアス一致など）→ 既存エントリーを使用
   3-3. 類似度が閾値未満 → ユーザーに選択を求める：
        - 候補A: 最も近い既存エントリーを使用
        - 候補B: 新規エントリーとして追加（ユーザー承認必須）
4. ユーザーが新規追加を承認 → マスタに追加
5. ユーザーが却下 → 既存から手動選択
```

**判断基準：**
- エイリアス完全一致 → 既存エントリーを自動使用
- 部分一致・類似語 → 既存エントリーを提案（確認なし）
- 該当なし → ユーザー判断を必須とする

### 実装上の注意

- `constructionMaster.ts` を直接編集するコードをAI解析フローに含めない
- 新規エントリーは `pendingEntries` などの一時領域に保存
- UIで承認フローを経由してからマスタに反映
- デフォルトマスタとユーザー追加分を区別して管理
